# LiliaDB Android SDK (`io.liliadb`)

Official Kotlin SDK for **LiliaDB**, the local-first multimodel embedded database
written in Rust, on Android (phones, Wear OS, and Android TV).

The SDK is a Gradle library module shipping:

- **Generated Kotlin bindings** (`uniffi.lilia_ffi`) produced by [UniFFI] from the
  universal C-ABI surface of `crates/lilia-ffi`.
- **Prebuilt JNI shared libraries** (`liblilia_ffi.so`) for `arm64-v8a`,
  `armeabi-v7a`, and `x86_64`, loaded through [JNA].

[UniFFI]: https://github.com/mozilla/uniffi-rs
[JNA]: https://github.com/java-native-access/jna

---

## 1. Key Features

- **Multimodel, transactional**: Key/Value, JSON documents, Graph, Full-Text
  Search (FTS5), and declarative SQL share a single SQLite ACID database file.
- **Async & blocking APIs**: every operation is exposed both as a Kotlin
  `suspend` function and as a `*Sync` blocking variant for main-thread-free,
  coroutine-friendly usage.
- **Resource profiles**: tuned SQLite cache / WAL / mmap settings for phones
  (`MOBILE`), wearables and TV dongles (`CONSTRAINED`), or server-class hardware
  (`SERVER`).
- **Encryption at rest**: transparent authenticated AES-256-GCM via a raw
  256-bit key or a passphrase (PBKDF2-HMAC-SHA256 key derivation).
- **Exact 64-bit versioning**: entries carry `ULong` versions, without IEEE-754
  precision loss.
- **Mobile lifecycle aware**: `prepareForBackground()` flushes the WAL before the
  OS suspends the process; `close(timeoutMs)` drains in-flight work gracefully.
- **Broad device support**: `minSdk 21` covers Android 5.0+, Wear OS 1.0+, and
  Android TV.

## 3. Installation

The SDK is consumed as a local Gradle library module; it is not published to a
Maven repository in the v0.1 distribution.

### 3.1 Include the module

In your app's `settings.gradle.kts`, point a module at the checked-out
`packages/android-sdk` directory:

```kotlin
include(":lilia-android")
project(":lilia-android").projectDir = file("../liliadb/packages/android-sdk")
```

### 3.2 Add the dependency

In your app's `app/build.gradle.kts`:

```kotlin
dependencies {
    implementation(project(":lilia-android"))
}

android {
    defaultConfig {
        ndk {
            // Keep in sync with the shipped prebuilds; x86_64 is for emulators.
            abiFilters += listOf("arm64-v8a", "armeabi-v7a", "x86_64")
        }
    }
}
```

The module packs `liblilia_ffi.so` from `release/android/jniLibs` (configured
through its `jniLibs.srcDirs`), so keep the LiliaDB repository checkout at the
relative location referenced by `settings.gradle.kts`, or copy the `jniLibs`
folder next to the module and adjust `build.gradle.kts` accordingly.

### 3.3 Import

All bindings live in the generated `uniffi.lilia_ffi` Kotlin package:

```kotlin
import uniffi.lilia_ffi.FfiResourceProfile
import uniffi.lilia_ffi.LiliaDatabase
```

## 4. Building the Native Library & Bindings

Native artifacts and Kotlin bindings are (re)generated by the repository's
Android packaging script:

```bash
# One-time setup
cargo install cargo-ndk
export ANDROID_NDK_HOME=/path/to/android-ndk

# From the repository root
./tools/mobile/build-android.sh
```

The script:

1. Builds the host-side `uniffi-bindgen` CLI and the `lilia-ffi` dylib.
2. Regenerates `packages/android-sdk/src/main/java/uniffi/lilia_ffi/lilia_ffi.kt`
   from the current Rust interface.
3. Cross-compiles `lilia-ffi` in release mode for
   `aarch64-linux-android` (`arm64-v8a`), `armv7-linux-androideabi`
   (`armeabi-v7a`), and `x86_64-linux-android` (`x86_64`) into
   `release/android/jniLibs/`.
4. Rewrites `packages/android-sdk/build.gradle.kts`.

Continuous integration (`.github/workflows/mobile-targets.yml`) runs the script on
every pull request touching `crates/**` or `tools/mobile/**` to verify Kotlin
binding generation against the Android toolchain targets.

### Package structure

```
packages/android-sdk/
├── build.gradle.kts                            # Android library module
└── src/main/java/uniffi/lilia_ffi/
    └── lilia_ffi.kt                            # Generated UniFFI Kotlin bindings
```

## 5. Quick Start

```kotlin
import uniffi.lilia_ffi.FfiResourceProfile
import uniffi.lilia_ffi.LiliaDatabase

class AppRepository(context: Context) {
    private val db = LiliaDatabase.open(
        path = File(context.filesDir, "app.lilia").absolutePath,
        profile = FfiResourceProfile.MOBILE,
        encryptionKey = null, // or a 32-byte ByteArray
    )

    fun bootstrap() {
        // 1. Key/Value (binary-safe)
        db.kvSetSync(
            "sessions", "sess:1".toByteArray(), "tok_abc".toByteArray(),
            expiresAtMs = System.currentTimeMillis() + 3_600_000,
        )

        // 2. JSON documents
        db.jsonPutSync("users", "usr:1", """{"name":"Alice","role":"admin"}""")

        // 3. Graph
        db.graphSetNodeSync("social", "usr:1", "User", """{"name":"Alice"}""")
        db.graphAddEdgeSync("social", "usr:1", "usr:2", "FOLLOWS")

        // 4. Full-text search
        db.ftsIndexSync("articles", "art:1", "LiliaDB delivers local-first multimodel storage.")

        // 5. Declarative SQL
        val rows = db.sqlQuerySync(
            "SELECT id FROM lilia_json WHERE space = 'users'",
            paramsJson = null,
        )
    }

    fun close() {
        db.closeSync(5_000uL)
    }
}
```

## 6. Opening a Database

```kotlin
// Raw 256-bit key (exactly 32 bytes, otherwise a Crypto error is thrown)
val key = SecureRandom().generateSeed(32)
val db = LiliaDatabase.open(path, FfiResourceProfile.MOBILE, encryptionKey = key)

// Passphrase with PBKDF2-HMAC-SHA256 key derivation
val db2 = LiliaDatabase.openWithPassphrase(path, FfiResourceProfile.MOBILE, "correct horse")

// Unencrypted
val db3 = LiliaDatabase.open(path, FfiResourceProfile.CONSTRAINED, encryptionKey = null)
```

- `path` is the database file path; use app-private storage such as
  `Context.filesDir` (or `noBackupFilesDir` to exclude it from cloud backups).
- When a key or passphrase is supplied, transparent authenticated AES-256-GCM
  encryption protects values, vectors, and WAL frames on disk.

### Resource Profiles

| Profile                          | Tuned for                         | Durability | Busy timeout | Writer queue | Read pool | WAL checkpoint | mmap     | Page cache |
| -------------------------------- | --------------------------------- | ---------- | ------------ | ------------ | --------- | -------------- | -------- | ---------- |
| `FfiResourceProfile.SERVER`      | Server-class hardware             | `durable`  | 5 000 ms     | 64           | 4         | 16 MB / 5 s    | 256 MB   | 64 MB      |
| `FfiResourceProfile.MOBILE`      | Phones, Wear OS, Android TV       | `balanced` | 5 000 ms     | 32           | 2         | 4 MB / 3 s     | 32 MB    | 8 MB       |
| `FfiResourceProfile.CONSTRAINED` | Wear OS 32-bit, budget TV dongles | `balanced` | 3 000 ms     | 16           | 1         | 1 MB / 1.5 s   | disabled | 2 MB       |

`LiliaDatabase` implements `AutoCloseable`, so `use { }` also works:

```kotlin
LiliaDatabase.open(path, FfiResourceProfile.MOBILE, null).use { db ->
    db.jsonPutSync("events", "evt:1", """{"kind":"tap"}""")
}
```

Note: `use { }` and `AutoCloseable.close()` only release the native FFI handle.
For a graceful shutdown that drains in-flight operations first, call the
explicit `close` / `closeSync` with a timeout instead (see section 13).

## 7. Threading Model

Every operation comes in two flavors:

- **`suspend` variants** (`kvSet`, `jsonGet`, `ftsSearch`, ...): integrate with
  Kotlin coroutines. The call is dispatched to the Rust async executor and the
  coroutine resumes on completion — safe to call from `Dispatchers.Main`.
- **`*Sync` variants** (`kvSetSync`, `jsonGetSync`, `ftsSearchSync`, ...):
  execute the FFI call inline on the calling thread. Never call them from the
  Android main thread; dispatch to `Dispatchers.IO` instead.

```kotlin
scope.launch {
    // Suspend API — safe on any dispatcher
    db.jsonPut("events", "evt:1", """{"kind":"tap","ts":1730000000}""")
    val hits = db.ftsSearch("articles", "multimodel storage", limit = 10u)

    // Sync API — must run off the main thread
    withContext(Dispatchers.IO) {
        db.sqlQuerySync("SELECT id FROM lilia_json WHERE space = 'events'", paramsJson = null)
    }
}
```

## 8. Key/Value (`kv*`)

Keys and values are binary `ByteArray`. `kvSet` returns the new `ULong` version.

```kotlin
val version: ULong = db.kvSetSync(
    "sessions",
    "sess:1".toByteArray(),
    "tok_abc".toByteArray(),
    expiresAtMs = System.currentTimeMillis() + 3_600_000, // or null for no TTL
)

val entry: FfiKvEntry? = db.kvGetSync("sessions", "sess:1".toByteArray())
entry?.let {
    val value = it.value.decodeToString()
    val expiresAt = it.expiresAtMs // Long?, null when no TTL
}

// Keyset-paginated scan; `after` is an exclusive cursor (pass the last key of
// the previous page), `limit` caps the page size.
var after: ByteArray? = null
do {
    val page: List<FfiKvEntry> = db.kvScanSync("sessions", after = after, limit = 100u)
    page.forEach { /* ... */ }
    after = page.lastOrNull()?.key
} while (page.isNotEmpty())

val deleted: Boolean = db.kvDeleteSync("sessions", "sess:1".toByteArray())
```

`FfiKvEntry` is
`{ namespace: String, key: ByteArray, value: ByteArray, version: ULong, expiresAtMs: Long? }`.

## 9. JSON Documents (`json*`)

Documents are passed as JSON strings (`valueJson`); parse them with
`kotlinx.serialization`, `org.json`, or any JSON library. `jsonPut` returns the
new `ULong` version.

```kotlin
val version: ULong = db.jsonPutSync("users", "usr:1", """{"name":"Alice","role":"admin"}""")

val doc: FfiJsonEntry? = db.jsonGetSync("users", "usr:1")
val name = doc?.valueJson?.let { JSONObject(it).optString("name") }

val deleted: Boolean = db.jsonDeleteSync("users", "usr:1")

// Filtered query: a JSON object of field-equality predicates combined with AND.
// Array fields match when any element equals the value (multikey).
val admins: List<FfiJsonEntry> = db.jsonFindSync(
    "users",
    """{"role":"admin"}""",
    afterId = null, // exclusive keyset cursor, like kvScan's `after`
    limit = 50u,
)
```

`FfiJsonEntry` is
`{ space: String, id: String, valueJson: String, version: ULong }`.

## 10. Graph (`graph*`)

```kotlin
db.graphSetNodeSync("social", "usr:1", "User", """{"name":"Alice"}""")
db.graphSetNodeSync("social", "usr:2", "User", """{"name":"Bob"}""")
db.graphAddEdgeSync("social", "usr:1", "usr:2", "FOLLOWS")

val node: FfiGraphNode? = db.graphGetNodeSync("social", "usr:1")

val neighbors: List<String> = db.graphNeighborsSync(
    "social",
    "usr:1",
    FfiDirection.OUTGOING, // OUTGOING | INCOMING | BOTH
    kindFilter = "FOLLOWS", // or null for all edge kinds
)

// Includes the starting nodes and every reachable node.
val network: List<String> =
    db.graphReachabilitySync("social", listOf("usr:1"), FfiDirection.OUTGOING)

val removedEdge: Boolean = db.graphRemoveEdgeSync("social", "usr:1", "usr:2", "FOLLOWS")
val removedNode: Boolean = db.graphDeleteNodeSync("social", "usr:2")
```

`FfiGraphNode` is `{ graph: String, id: String, kind: String, metadataJson: String }`.
The record `FfiGraphEdge` (`graph`, `source`, `target`, `kind`) is also part of
the generated bindings.

## 11. Full-Text Search (`fts*`)

SQLite FTS5 with BM25 ranking and snippet extraction.

```kotlin
db.ftsIndexSync("articles", "art:1", "LiliaDB delivers local-first multimodel storage.")

val hits: List<FfiFtsHit> = db.ftsSearchSync("articles", "multimodel storage", limit = 5u)
hits.forEach { hit ->
    Log.d("Lilia", "${hit.docId}: rank=${hit.rank} snippet=${hit.snippet}")
}

db.ftsDeleteSync("articles", "art:1")
```

`FfiFtsHit` is `{ collection: String, docId: String, snippet: String, rank: Double }`.

## 12. Declarative SQL (`sqlQuery`)

SQLite views over the multimodel storage:

| View                | Columns                                                           |
| ------------------- | ----------------------------------------------------------------- |
| `lilia_json`        | `(space, id, value, version)` — decoded plaintext JSON            |
| `lilia_kv`          | `(namespace, key, value, version, expires_at_ms)` — decoded bytes |
| `lilia_graph_nodes` | `(graph, id, kind, metadata)`                                     |
| `lilia_graph_edges` | `(graph, source, target, kind)`                                   |

Positional parameters are bound by passing a JSON array of values as
`paramsJson` (or `null` for none):

```kotlin
val result: FfiSqlQueryResult = db.sqlQuerySync(
    """
    SELECT id, json_extract(value, '$.name') AS name
    FROM lilia_json
    WHERE space = ?1
    """.trimIndent(),
    paramsJson = """["users"]""",
)

result.columns      // ["id", "name"]
result.rowsJson    // each row serialized as a JSON array, e.g. """["usr:1","Alice"]"""
result.rowsAffected // 0 for SELECT, mutation count otherwise
```

## 13. Maintenance, Backup & Lifecycle

```kotlin
// SQLite PRAGMA quick_check integrity verification
val ok: Boolean = db.quickCheckSync()

// Explicit WAL checkpoint
db.checkpointSync()

// Atomic online backup to another file
db.backupSync("${context.filesDir}/backup.lilia")

// Graceful close: drain accepted in-flight operations, then release resources.
db.closeSync(5_000uL) // timeout in milliseconds, as ULong
```

- `close` drains accepted in-flight operations before releasing resources; the
  timeout bounds the wait in milliseconds.
- Operations started after `close` fail.
- The `suspend` variants `quickCheck`, `checkpoint`, `backup`, and `close` behave
  identically for coroutine-based callers.

### Android Lifecycle Integration

`prepareForBackground()` flushes the WAL and commits pending pages before the
OS suspends your process — call it when your app goes to the background:

```kotlin
class LiliaLifecycleObserver(private val db: LiliaDatabase) : DefaultLifecycleObserver {
    override fun onStop(owner: LifecycleOwner) {
        db.prepareForBackground()
    }
}

// In your Application class
ProcessLifecycleOwner.get().lifecycle.addObserver(LiliaLifecycleObserver(db))
```

## 14. Error Handling

All operations throw `LiliaFfiException`, a sealed class with a `v1: String`
message payload:

| Variant                          | Meaning                                                              |
| -------------------------------- | -------------------------------------------------------------------- |
| `LiliaFfiException.Storage`      | SQLite / storage engine failure                                      |
| `LiliaFfiException.InvalidInput` | Malformed JSON, invalid key length, bad arguments                    |
| `LiliaFfiException.NotFound`     | Requested entry does not exist                                       |
| `LiliaFfiException.Conflict`     | Optimistic concurrency or busy conflict                              |
| `LiliaFfiException.Crypto`       | Encryption / decryption failure (e.g. wrong key, invalid key length) |
| `LiliaFfiException.Generic`      | Any other engine error                                               |

```kotlin
try {
    db.jsonPutSync("users", "usr:1", payload)
} catch (e: LiliaFfiException.InvalidInput) {
    Log.w("Lilia", "Malformed JSON payload: ${e.v1}")
} catch (e: LiliaFfiException.Crypto) {
    Log.e("Lilia", "Decryption failed (wrong key?): ${e.v1}")
} catch (e: LiliaFfiException) {
    Log.e("Lilia", "Database error: ${e.message}")
}
```

## 15. R8 / ProGuard

The JNA AAR ships its own consumer rules. Because the generated bindings are
resolved through JNA's interface proxying, keep them from being renamed when
full minification is enabled — add to your app's `proguard-rules.pro`:

```proguard
-keep class uniffi.lilia_ffi.** { *; }
```

## 16. API Reference

Every method exists as a `suspend` function and as a `*Sync` blocking variant
(except `prepareForBackground`, which is sync-only).

| Area        | Methods                                                                                                                     | Notes                                                     |
| ----------- | --------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------- |
| Open        | `LiliaDatabase.open`, `LiliaDatabase.openWithPassphrase`                                                                    | Companion constructors; profile + optional key/passphrase |
| KV          | `kvSet`, `kvGet`, `kvScan`, `kvDelete`                                                                                      | Binary keys/values; TTL via `expiresAtMs`                 |
| JSON        | `jsonPut`, `jsonGet`, `jsonDelete`, `jsonFind`                                                                              | JSON strings; equality filters with keyset pagination     |
| Graph       | `graphSetNode`, `graphGetNode`, `graphDeleteNode`, `graphAddEdge`, `graphRemoveEdge`, `graphNeighbors`, `graphReachability` | `FfiDirection.OUTGOING` / `INCOMING` / `BOTH`             |
| FTS         | `ftsIndex`, `ftsSearch`, `ftsDelete`                                                                                        | FTS5, BM25 rank, snippets                                 |
| SQL         | `sqlQuery`                                                                                                                  | Views + positional JSON params                            |
| Maintenance | `checkpoint`, `backup`, `quickCheck`, `prepareForBackground`, `close`                                                       | `close(timeoutMs: ULong)`                                 |
